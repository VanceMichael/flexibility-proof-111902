# 凭据流程（调度员 ↔ 财务）

把资源商接口、调度指令和计量补录接到结算凭据流程的本地服务。
从演练来源（`npm start`，默认 `http://127.0.0.1:3100`）只读拉取资料，
把有根据的确认与冲正凭据提交到来源的 `/finance/receipts`。

## 运行

```bash
npm start          # 终端 1：演练来源（阶段 0）
npm run flow       # 终端 2：凭据流程，默认 http://127.0.0.1:3200
```

环境变量：`PORT`（流程端口）、`SOURCE_ORIGIN`（来源地址）、
`REQUEST_FILE`（业务请求，默认 `requests/example.json`，给出调度日、
目标调用与时区）。

- `http://127.0.0.1:3200/dispatch` 调度员视图：目标区间与调用优先关系、
  出口主从计量关系、可结算切片，以及可点开的**待补采范围**（哪段缺数、
  哪段暂缓、何时重试）。
- `http://127.0.0.1:3200/finance` 财务视图：待领的确认/冲正凭据（附根据）、
  已领台账、按调用 × 物理出口的净认可量、冲正溯源说明。
- `GET /flow/api/state` 全部状态的 JSON。

演练推进：向来源 `POST /replay/phase {"phase":1}` 后，在任一页面点
「同步来源 / 重新归集」，流程会算出撤回引起的冲正与改认的确认。

## 口径约定

- **归属**：按物理出口（outlet）计算。相同 outlet 即同一物理出口，
  站点编号只是报数别名，同一计量片只认列一次；从表
  （`parent` + `independent:false`）的量已含在主表内，不重复计量。
  同一时刻同一出口 priority 大者优先；高优先调用撤回的时段让给仍
  有效的低优先调用。
- **切片**：切片端点必须同时是计量与基线提供的分界点；量不按比例
  摊到未提供分界点的区间。净认可量 = 基线 − 实测（同一出口同一切片）。
- **计量**：`quantity` 直接是区间量；`counter` 取相邻表码差。表码
  复位凭独立的 `resetAt` 事件解释（复位前用 `before` 收口、复位后
  从 `after` 起算）；没有复位事件的回退记为数据问题，不填零穿缺口。
- **领取**：以资源商报告的开放范围与暂缓（hold + retryAfterSeconds）
  为准；某出口某段的缺口只影响该段，其余独立窗口照常处理。
- **冲正**：已领凭据的段落被撤回或修订时，先出冲正（`netKwh` 取负、
  带 `priorReceipt`），同一物理区间的新确认在冲正领走前保持挂起，
  账面不会两边同时认列。量未变的修订（如只扩覆盖、补复位事件）
  不动账面，只在溯源中说明。
- **经办号**：`FP<调度日>-<调用>-<出口>-<起>-<止>-<C|R><序号>`，
  按内容确定生成，网络重试不会产生重复受理（来源按号去重）。
- **台账**：每笔凭据记录领取号、调用、物理出口、采用的读数版本
  （样本修订 / 基线修订）与同步批次；被冲正的凭据保留「曾可用」的
  根据与冲正原因。台账为进程内存态，来源复位后请重启流程。

## 模块

- `flow/planner.mjs` 纯规划：归属、覆盖、切片、待补采、对账（可单测）。
- `flow/ledger.mjs` 台账与经办号。
- `flow/source-client.mjs` 来源接口封装。
- `flow/server.mjs` 页面与动作（同步、领取、核对）。
- `flow/time.mjs` 当地时刻与带时区的凭据窗口。
